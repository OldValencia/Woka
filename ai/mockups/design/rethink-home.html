Home as a library

Home is a grid built for many linked folders. In practice a person links one or two, once, and never opens the list again — so the screen costs a click at every launch and says nothing that changed. This is the answer: keep the grid, keep Home, shrink the dock, and change what Home holds.

What is wrong now

01

The grid is composed for a gallery

GridCells.Adaptive with padding(top 20, start 40, end 40, bottom 120). Two folders land as two tiles in the corner of an empty window — not minimal, unresolved.

Compose for what the screen holds: one row is centred, many rows fill.
02

Linking has no affordance on the screen

A + injected into the dock and a right-click on the background. Nothing on Home says a folder can be added; the empty state is the words “No linked folders”.

A tile in the grid, and a folder dropped in from Explorer.
03

Pinned exists and is invisible

PinnedSession already holds a folder inside a root plus the scroll position you left it at. It is offered only in a hover popup in the dock, and never on Home.

Pinned is the other half of the library. It belongs on the screen.
04

The dock has a destination that is not one

“Library” lights up while you are in a folder, carries a badge, opens a hover popup of a different set of folders — and clicking it does nothing at all.

Remove it. You are in a folder, never “in the library”.

The proposal

A

Home is the library, not a list of shortcuts

Two zones on one screen: the roots you linked, and the places you pinned inside them. Roots are stable and few; pins change every week. The screen is worth opening because half of it moves. Both zones reorder by drag.

B

“Open at launch” is a flag, not a position

Set from the card's own menu and from a control on the card, shown as a badge, stored in settings.json. Position means nothing anywhere, so dragging for looks can never change what opens tomorrow.

C

Launch stays predictable

Home opens unless a folder carries the flag. Either way the user set it and can see it. Nothing is inferred from history.

D

The dock shrinks to four

Link, Home, Search, Settings. Library goes; the folder list lives on Home, which is one click away in the same dock. A small dock that tells the truth beats a full one that does not.

  • 1A flag on the card, never a position. An earlier draft made the first grid cell mean “opens on launch”. It does not survive one folder — the only card is always first — and it would make ordering for looks change tomorrow's launch silently.
  • 2Two ways in, one state. The card's context menu carries a checked Open at launch; the same badge, hollow, is the hover control in the card's corner. Setting it on one card clears it everywhere else.

Why Library goes rather than gets fixed

It lit up while you were in a folder, which said you were somewhere you cannot be. Its popup listed a set of folders Home does not show. Its click did nothing. Once pinned folders are on Home, the popup has nothing left that Home does not say better — and Home is one click away in the same dock.

What remains is deliberately small: the action that builds the library, the library, and the two things that are not navigation at all. If the dock later earns a fifth item, it will be because something needed a home — not because a row looked empty.

Three ways, one action

The tile in the grid, last, always visible. The dock's +, which is where it already lives. A folder dragged from Explorer onto the window — accepted on Home and inside a folder view alike.

The third does not exist anywhere in the app today: there is no OS drag-and-drop in the code at all, though general_idea.md names drag-and-drop a desktop pillar. Linking is the one action where dragging is the obvious gesture, and it is the only one that works for a person who never opens a context menu.

Dropping a file rather than a folder is the quick-preview case and is not this: it opens the viewer, and the folder is offered afterwards as it already is on launch.

Why this is not cosmetic

Unlink fires immediately from the card menu and from the × on hover, with no confirmation. withoutFolder then sweeps everything under that path prefix: watchRecords, trackPrefsPerFile, trackPrefsPerFolder. One mis-click erases the watch history and the chosen audio and subtitle tracks for a whole tree.

A confirm dialog on every unlink punishes the common case to guard the rare one. A banner that holds the removed records for a few seconds costs nothing when you meant it, and costs nothing when you did not.

What this does not add

—

No third list

No recents. Linked folders and pinned places are the two lists that already exist; this shows them, it does not invent another.

—

No launch dropdown

The flag lives on the card it affects and is stored like any other preference. A setting three screens away from the object would be the same answer, further from the question.

—

No inference

Nothing opens because of what you did yesterday. Every launch is something the user placed there on purpose.

Still open: whether Pinned sits above or below the roots once both are full, and whether a pinned card needs more than the breadcrumb line to separate two folders both called Season 1.
