# Исправления видеоплеера и превью (Запланировано)

## Текущие проблемы
1. **"File is too big to fit in memory" при открытии тяжелых видео (например, MKV):**
   Приложение пытается загрузить видеофайл целиком в оперативную память. Это происходит из-за ошибки в `NativeMediaViewer.kt`, где `loadThumbnail` вызывает `item.file.readBytes()` абсолютно для всех файлов, включая гигабайтные фильмы.
2. **Бесконечная загрузка и отсутствие контролов у видео:**
   Даже если видео маленькое и помещается в память, `Image.makeFromEncoded()` не умеет парсить видеоформаты и возвращает `null`. В `MediaViewerScreen.kt` интерфейс плеера (поверхность видео и панель управления) скрыт за проверкой `if (state.imageBitmap != null)`. В результате плеер и контролы не рендерятся, и пользователь видит только вечный `CircularProgressIndicator` (хотя пробел ставит видео на паузу, так как ловится глобальным обработчиком контейнера).

## Решение (План реализации)

1. **Оптимизация `loadThumbnail` (Генерация превью для видео):**
   - Убрать `readBytes()` для видеофайлов.
   - Использовать FFmpeg (через `ProcessBuilder` или JavaCV) для извлечения первого кадра.
   - **Кэширование:** Сохранять сгенерированные кадры на диск (например, `.jpg`) в скрытую папку `user.home/Documents/OldValencia/Iris/.thumbnails/`. Это позволит быстро загружать превью даже если в папке 1000 видеофайлов, избегая повторной генерации.
   - **Многопоточность:** Ограничить количество параллельных процессов FFmpeg (например, `Dispatchers.IO.limitedParallelism(4)`), а также реализовать ленивую генерацию превью (создавать только когда видео отображается в списке/сетке).

2. **Исправление `MediaViewerScreen.kt`:**
   - Изменить условие рендера: не блокировать отрисовку интерфейса плеера (и контролов), если `state.imageBitmap == null`, при условии, что текущий файл — это видео (`activeItem is MediaItem.Video`).
   - Пока превью грузится, можно показывать заглушку, но контролы и плеер должны работать независимо от превью.

## Глобальный плеер (Picture-in-Picture) и Унификация шорткатов

1. **Глобальная архитектура (Отвязка плеера от папки):**
   - Вынести стейт плеера (`VideoPlayerState`, путь к файлу, масштаб) на уровень всего приложения (Global State/Koin).
   - Окно `MediaViewerFullscreenWindow` должно создаваться независимо от `MediaViewerScreen`.
   - Если пользователь переходит в другую папку в главном приложении, открытое окно PIP не закрывается и видео продолжает играть.

2. **Унификация управления контентом и окном:**
   - Модификатор управления: **`Ctrl`** (на Windows) / **`Cmd`** (на Mac).
   - **Зуммирование контента:** `Ctrl` + Scroll.
   - **Перемещение контента (Pan):** `Ctrl` + Левая кнопка мыши (Drag).
   - **Перемещение окна (PIP):** Простой Drag левой кнопкой мыши по любой точке видео (без зажатого `Ctrl`) перемещает само окно по рабочему столу.

3. **Свойства PIP окна:**
   - Окно изначально открывается в режиме `WindowPlacement.Maximized` (безрамочное, не эксклюзивное).
   - В заголовок окна `Window(title = ...)` передаётся имя текущего файла (вместо Untitled).
   - Окно можно свободно уменьшать и изменять в размерах (оставляем `undecorated = true`, так как ресайз работает на стороне пользователя ОС).
   - В будущем: Always on Top и Click-through.

4. **Абстракция диалоговых окон (Рефакторинг `FileInfoDialog.kt`):**
   - Выстроить строгую иерархию: `AbstractDialog` -> `InformationDialog` / `ConfirmationDialog` / `ErrorDialog` -> `[SpecificDialogs]`.
     - `InformationDialog` — информационный диалог с одной кнопкой "Close" (от него наследуется `FileInfoDialog`).
     - `ConfirmationDialog` — диалог с двумя кнопками (Да / Нет) для подтверждения действий.
     - `ErrorDialog` — аналог InformationDialog, но с акцентом на ошибку.

5. **Поведение при открытии нового видео (Конфликт с PIP):**
   - Если PIP-окно уже открыто и играет видео, а пользователь кликает на **другое** видео в главном приложении:
   - Показываем наследника `ConfirmationDialog` — например, `VideoAlreadyOpenedDialog`. Этот диалог должен рендериться поверх **главного окна** приложения (там, где сейчас находится фокус и курсор пользователя).
   - Текст: *"Вы уже смотрите видео. Закрыть текущее видео и открыть новое?"*
   - Если пользователь выбирает "Да" -> текущее видео в PIP закрывается, открывается новое.
   - Если выбирает "Нет" -> новое видео не открывается, продолжаем смотреть текущее.

6. **Очистка памяти (Lifecycle):**
   - При принудительном закрытии окна PIP (крестик, Alt+F4 или программное закрытие) глобальный менеджер обязан вызвать `.dispose()` у экземпляра `VideoPlayerState`, чтобы избежать утечек памяти (освободить ресурсы VLC).
