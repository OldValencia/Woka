# ME-001 — Toolchain and dependency refresh

| | |
|---|---|
| **Order** | 1 |
| **Depends on** | nothing |
| **Feature** | [Image Editor](../../image-editor.md) |

**Goal.** Bring the build to current stable versions and delete what is not used, before eight new
packages land on top of it.

**Why now.** Every version bump after this ticket has to be regression-tested against editor code as
well as viewer code. Doing it on a tree with no editor in it isolates the blame.

## Steps

1. `gradle/libs.versions.toml` — bump, one commit-sized group at a time so a failure is attributable:
   - `androidx-lifecycle` `2.11.0-beta01` → `2.11.0` — the stable of the same line; a beta is pinned
     here for no reason;
   - `koin` `4.0.0` → `4.2.2`;
   - `kotlinx-serialization` `1.7.3` → `1.11.0` (the editor's document schema rides on it);
   - `coil3` `3.0.4` → `3.5.0`;
   - `kotlin` `2.4.0` → `2.4.10` — `composeCompiler` follows `kotlin` and needs no separate change.
2. Delete the `filekit` version, the `filekit-compose` library entry (there is only one — no
   `filekit-core`), and `implementation(libs.filekit.compose)` from `shared/build.gradle.kts`. Nothing imports
   `io.github.vinceglb` anywhere in `shared/src` — folder picking goes through the AWT `FileDialog` in
   `core/ui/dialogs/Dialogs.kt`. Grep to prove it before deleting, and again after.
3. Leave `javacv` / `ffmpeg-platform` alone — they move in ME-013, immediately after, with the manual
   video pass re-run. A decode-behaviour change does not ride along with five mechanical bumps.
4. Do **not** bump `material3`. The whole line is pre-release (newest `1.12.0-alpha03`) and the
   dependency is deleted outright in ME-014.
5. Do **not** bump `composeMultiplatform` or `kotlinx-coroutines`, and leave the
   `foojay-resolver-convention` plugin in `settings.gradle.kts` alone. `material3 1.11.0-alpha07`
   tracks the `composeMultiplatform 1.11.1` line, so moving Compose before ME-014 drags a pre-release
   `material3` along with it — the exact coupled regression this ticket exists to keep out. Compose
   moves once, after `material3` is gone. Coroutines is silent for the same reason a bump needs a
   reason: nothing here asks for it.
6. `gradle/wrapper/gradle-wrapper.properties` — `9.6.1` → `9.7.0`. The plain
   `./gradlew.bat wrapper --gradle-version 9.7.0 --distribution-type bin` **fails** on this repo:
   the properties file pins `distributionSha256Sum`, and the `wrapper` task will not invent a
   replacement for a pin it did not compute. Pass it:

   ```
   ./gradlew.bat wrapper --gradle-version 9.7.0 --distribution-type bin \
     --gradle-distribution-sha256-sum <sum>
   ```

   Take `<sum>` from `https://downloads.gradle.org/distributions/gradle-<v>-bin.zip.sha256` and
   cross-check it against `https://services.gradle.org/versions/current`. For 9.7.0 both give
   `84fbba45c7f4c64abc77460e1c00f541e9f960e3c7ed2538f1ede19eacd873ae`. The task runs twice —
   once under the old wrapper, once under the freshly downloaded one — and rewrites `gradle-wrapper.jar`,
   `gradlew` and `gradlew.bat` as well as the properties, adding the 9.7 template's `retries` and
   `retryBackOffMs` keys.
7. Clear the Gradle-10 deprecations the 9.7.0 wrapper then reports, because they are the same build
   debt and this is the same tree without an editor on it. Not a bump — no version moves, only DSL:
   - `shared/build.gradle.kts` — `val jvmMain by getting { dependencies { … } }` and the same for
     `jvmTest` become `jvmMain.dependencies { … }` / `jvmTest.dependencies { … }`, which is what the
     `commonMain` and `commonTest` blocks four lines away already do;
   - `desktopApp/build.gradle.kts` — `implementation(compose.components.resources)` becomes
     `implementation(libs.compose.components.resources)`, the same catalog entry `shared` already uses.

   Verify with `--warning-mode all`: the "Deprecated Gradle features were used in this build" footer
   must be gone, not merely quiet.

Versions were read from `repo1.maven.org` on 2026-08-16. `search.maven.org` lags by months — it
reported `kotlin-stdlib 2.2.0` while this project was already on 2.4.0. Re-check the metadata, not the
search index.

## Files

`gradle/libs.versions.toml`, `shared/build.gradle.kts`, `desktopApp/build.gradle.kts`,
`gradle/wrapper/gradle-wrapper.properties` (plus `gradle-wrapper.jar`, `gradlew`, `gradlew.bat` —
regenerated by the `wrapper` task, not edited)

## Done when

- `./gradlew.bat :shared:build` green, with the same test count as before the bump;
- `./gradlew.bat :desktopApp:run` opens, a folder lists, a video plays;
- no `filekit` string left in the repo outside `ai/docs/features/implemented/`;
- `--warning-mode all` reports no deprecated Gradle features.

**Measured 2026-08-16.** Baseline and post-bump both 483 tests in 62 classes, 0 failures, 0 errors,
0 skipped. `:shared:build --rerun-tasks` and `:desktopApp:build --rerun-tasks` green, and green again
after step 7 with `--warning-mode all` clean.

Two things to expect and not chase: the first compile after the `kotlin` bump prints a
`FileNotFoundException` for a generated Compose-resources accessor and then recovers by compiling
non-incrementally — stale incremental state, gone on the next run. And `jvmTest` prints
`FileNotFoundException … woka-test*/settings.json` stack traces from the `SettingsStore` shutdown
hooks firing after their temp dirs are deleted; pre-existing, tests pass.
