# Dolby Vision Profile 5

## Цель и статус

Корректные цвета P5 в плеере, редакторе, постерах, hover, seek preview, сохранении кадра
и перекодированном экспорте. Использовать существующее преобразование HDR → SDR Woka
после восстановления цвета P5. Это не сертифицированный Dolby Vision display pipeline
и не новая система вывода HDR на монитор.

## Что уже есть

- Типизированный C-мост читает configuration и покадровые mapping/color metadata по заголовкам
  FFmpeg 8.1.2. Production converter восстанавливает BT.2020 PQ из текущих плоскостей/RPU.
- Guard проверяет capability и каждый RPU. Неподдержанные или отсутствующие данные дают
  явную ошибку; старый RPU или обычный YUV fallback не используются.
- На обоих P5 подтверждены RPU/metadata, совпадение seek/sequential и независимые reference pixels.
- Все обычные picture-grabbers используют общую базу; viewer имеет отдельный CUDA-адаптер.
  Входы бывают RGBA, BGR и RAW. RAW обслуживает также фильтры геометрии/деинтерлейсинга.
  Решение только внутри HDR painter оставило бы другие пути с неверными цветами.
- HdrInfo распознаёт P5 независимо от unspecified тегов и использует source/L1 из текущего кадра.
  RAW geometry сохраняет метаданные выхода фильтра; photo/encode проходят общий HDR stage.
  Remux P5 сохраняет configuration/RPU; `strict=unofficial` не даёт movenc потерять dvcC/dvvC.

## Последовательность работы

### 1. Метаданные и эталон

Расширить C-мост отдельным accessor для разобранных данных кадра. Проверять версию libavutil,
размеры, смещения и диапазоны до чтения; возвращать копию в собственном версионированном ABI.
Нельзя удерживать указатели на side data после следующего grab/seek/release.
Получить и записать коэффициенты polynomial/MMR, pivots, bit depths, матрицы, offsets,
source peak и доступные L1 для одинаковых кадров при последовательном чтении и seek.

Подготовить независимый reference через отдельную сборку FFmpeg с libplacebo либо mpv gpu-next.
Сохранить версию, SHA-256 бинарника и входных сэмплов, параметры, выбранные PTS и выходы.
Текущий ffmpeg из PATH — 8.0 essentials; проверка `-filters` 2026-11-12 не нашла libplacebo.
mpv в PATH не найден. Нужен отдельный исследовательский инструмент в build, не новая
зависимость поставляемого приложения и не замена встроенного FFmpeg.

Сначала сравнивать восстановленный BT.2020 PQ до тон-маппинга. SDR-картинки разных плееров
с разными tone curves не являются численным эталоном преобразования P5.
Reference считается независимой реализацией, а не доказательством Dolby-сертификации.

### 2. Прототип преобразования

Взять исходные 10-битные плоскости до swscale YUV → RGB. Восстановить компоненты по RPU,
применить покадровые матрицы и PQ в правильном порядке, получить общий цветовой вход Woka.
Выбор CPU/native или Skia shader сделать по корректности, скорости и стоимости интеграции.
Первый прототип изолировать от production; измерить 1080p60 и 4K59.94, а не только один кадр.

Отдельно определить chroma siting/upsampling, нормализацию кодов, порядок resize и reshaping,
precision и clipping. Не принимать фиксированные матрицы или делитель 1023/1024 без проверки.
Прогнать постоянные цвета, границы pivots, polynomial и MMR; реальные сэмплы могут не покрывать
все разновидности mapping. Порог ошибки зафиксировать после оценки precision reference,
до принятия результата; сохранять max/mean/P99 и расположение ошибок.

### 3. Интеграция как единое поведение

Один контракт выходного цвета для плеера, дорожек редактора, RAW-фильтров, постера, hover,
seek preview, Save frame as photo и Render video. Покадровые метаданные принадлежат тому же
PTS и поколению playback, что и пиксели. Отдельно проверить изменение размера, поворот,
seek назад, повтор, EOF, отмену и закрытие.

Поддержка профиля не равна доступности metadata одного конкретного кадра. Если обязательные
данные отсутствуют или не поддержаны, не использовать предыдущий RPU и не откатываться
к обычному YUV → RGB. Сохранять явный отказ в таком случае.

Только после проверки всех readers заменить текущую безусловную блокировку P5 проверкой
реальной возможности обработки. Проверить Done/Revert и существующий remux отдельно:
перекодированный SDR не должен получать ложные DV/HDR теги; копия пакетов должна сохранять
нужные DV данные. Старые ошибочные постеры должны быть инвалидированы.

### 4. Проверка результата

Оба P5 на нескольких одинаковых PTS, включая смену RPU; контрольные SDR, HDR10, P8.1,
P8.4, P7/P10. Сравнить все поверхности до lossy-кодирования, экспорт проверить декодированием.
Проверить malformed/truncated metadata и несовместимую native-версию без dereference.
Измерить длинный playback и repeated seek по CPU, RAM, native memory; убедиться, что side data
не накапливаются. Windows проверить здесь; macOS/Linux указывать отдельно по фактическим CI
и runtime-результатам. `:shared:build`, необходимые regression/UI проверки, anti-FQN и размер
Kotlin-файлов обязательны после изменений кода. Ручная проверка автора завершает приёмку.

## Точка продолжения — 2026-11-19

DV5-104 завершён на Windows; далее DV5-103 в [backlog](tickets/backlog.md). D3D11 colour/resize
подключён к общему P5 converter с CPU fallback. Шесть полноразмерных кадров побайтно

(900 frames, JVM приложения, до UI). Настройка включена только в playback grabbers/lanes.

~59.9 FPS в каждой, gaps >25 ms = 0, RAM процесса 2047–2658 MiB. Compose draw не измерялся.
Native CTest 3/3, 1,704 API checks; shared build, desktop compile и 1,689 unit/integration/UI
tests прошли без ошибок/пропусков. Автор 2026-11-19 проверил файл руками: «всё ок работает файл».
